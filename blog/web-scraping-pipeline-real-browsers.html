Building a Web Scraping Pipeline with Real Browsers

A practical guide to building production-grade scrapers that never get blocked.

Published July 17, 2026 · 10 min read

Web scraping in 2026 faces an escalating arms race. Anti-bot systems like Cloudflare Turnstile, DataDome, and Akamai Bot Manager use machine learning to detect and block automated traffic. Traditional approaches — rotating proxies, puppeteer/playwright, headless Chrome — become less effective every month.

The solution: use real browsers rented from real people. Each request comes from a genuine browser installation with an authentic fingerprint and a residential IP.

The Architecture

A production scraping pipeline with real browsers has four layers:

  1. Orchestrator — manages session lifecycle, queuing, and retries
  2. Browser Pool — rented browser sessions from Ceki Browser
  3. Extractor — parses and structures the scraped data
  4. Storage — persists results (database, S3, or webhook)

Step 1: Set Up the Browser Pool

import { CekiBrowser } from '@ceki/browser-sdk';

class BrowserPool {
  constructor(token, size = 5) {
    this.ceki = new CekiBrowser({ token });
    this.size = size;
    this.sessions = [];
  }

  async initialize() {
    for (let i = 0; i < this.size; i++) {
      const session = await this.ceki.rent({ headless: false });
      this.sessions.push(session);
      console.log(`Session ${session.id} ready`);
    }
  }

  async getSession() {
    // Round-robin session selection
    const session = this.sessions.shift();
    this.sessions.push(session);
    return session;
  }

  async replaceSession(session) {
    // Replace a session that got blocked or disconnected
    const idx = this.sessions.indexOf(session);
    if (idx !== -1) {
      await session.stop().catch(() => {});
      const newSession = await this.ceki.rent({ headless: false });
      this.sessions[idx] = newSession;
    }
  }

  async shutdown() {
    await Promise.all(
      this.sessions.map(s => s.stop().catch(() => {}))
    );
  }
}

Step 2: Implement the Scraper

async function scrapePage(session, url) {
  try {
    await session.navigate(url);

    // Wait for page to render
    await session.waitForSelector('#content', 10000);

    // Extract data via CDP
    const data = await session.evaluate(() => {
      return {
        title: document.title,
        description: document.querySelector('meta[name="description"]')?.content,
        h1: document.querySelector('h1')?.textContent,
        text: document.body.innerText.substring(0, 5000)
      };
    });

    // Take a screenshot for verification
    const filename = url.replace(/[^a-z0-9]/gi, '_') + '.png';
    await session.screenshot('/tmp/scrapes/' + filename);

    return { url, data, timestamp: new Date().toISOString() };
  } catch (err) {
    console.error(`Failed to scrape ${url}:`, err.message);
    return { url, error: err.message };
  }
}

Step 3: Run the Pipeline

const pool = new BrowserPool('your_token', 3);
await pool.initialize();

const urls = [
  'https://example.com/page1',
  'https://example.com/page2',
  'https://example.com/page3',
];

const results = [];
for (const url of urls) {
  const session = await pool.getSession();
  const result = await scrapePage(session, url);
  results.push(result);
  console.log(`Scraped ${url}: ${result.data?.title || 'ERROR'}`);
}

await pool.shutdown();
console.log(`Completed ${results.filter(r => r.data).length}/${urls.length} pages`);

Why Real Browsers Beat Headless + Proxies

The traditional approach (headless browser + proxy rotation) fails because anti-bot systems detect inconsistencies between the browser fingerprint and the IP:

  • Headless detection: navigator.webdriver, missing Chrome extensions, modified User-Agent
  • Fingerprint mismatch: canvas fingerprint from a Mac while the IP says Windows
  • Behavioral analysis: too-perfect mouse movements, zero scrolling, instant navigation
  • IP reputation: data center IPs are flagged as non-residential

Real browser sessions eliminate all four signals — the browser is genuine, the fingerprint matches the IP, and the behavior is naturally human because humans control the browser when they're not renting it.
