Getting Started with Browser Rental APIs: A Developer's Guide

Learn how to integrate browser rental APIs into your AI agent workflows using Python and JavaScript SDKs.

Published July 17, 2026 · 8 min read

AI agents are transforming how we interact with the web, but they face a fundamental limitation: most websites use anti-bot systems (CAPTCHAs, fingerprinting, rate limiting) that block headless browsers and simple HTTP clients. The solution? Real browsers, rented from real people.

Browser rental APIs like Ceki Browser provide programmatic access to real browser instances running on real devices worldwide. This guide walks through the integration process from scratch.

What is a Browser Rental API?

A browser rental API lets you request a live browser session — a real Chrome/Firefox instance running on someone else's computer — and control it remotely via WebSocket or CDP (Chrome DevTools Protocol). You get:

  • Real browser fingerprint — canvas, WebGL, audio, and font fingerprints from a real device
  • Residential IP — the browser runs on a real person's internet connection
  • Human-like interaction — mouse movements, keystrokes, and scrolling that look natural
  • CAPTCHA bypass — many CAPTCHA challenges are resolved automatically through the rental infrastructure

Prerequisites

  • Node.js 18+ or Python 3.8+
  • A Ceki Browser account (token-based authentication)
  • Basic familiarity with async/await patterns

Integration with the Ceki CLI

The fastest way to start is with the Ceki CLI. Install it and authenticate:

# Install the CLI
npm install -g ceki-cli

# Set your agent token
export CEKI_AGENT_TOKEN=your_token_here

# Rent a browser session
ceki rent --headless false

# Navigate to a URL
ceki navigate https://example.com

# Execute JavaScript in the page
ceki cdp --method Runtime.evaluate \
  --params '{"expression":"document.title"}'

# Click an element (with human-like mouse movement)
ceki click 500 300

# Type text into a field
ceki type "Hello, World!" --selector "#my-input"

# Stop the session when done
ceki stop

JavaScript SDK Integration

For programmatic control, use the Ceki JavaScript SDK:

import { CekiBrowser } from '@ceki/browser-sdk';

const browser = new CekiBrowser({
  token: 'your_agent_token',
  endpoint: 'https://api.ceki.me/mcp/agent'
});

// Rent a browser
const session = await browser.rent({ headless: false });
console.log(`Session ID: ${session.id}`);

// Navigate to a page
await session.navigate('https://example.com/login');

// Fill out a login form
await session.type('#username', 'myuser');
await session.type('#password', 'mypassword');
await session.click(400, 300);

// Wait for navigation
await session.waitForNavigation();

// Extract data
const title = await session.evaluate(
  () => document.title
);

// Take a screenshot
await session.screenshot('/tmp/page.png');

// Clean up
await session.stop();

Python SDK Integration

The Python SDK offers similar functionality:

from ceki import CekiBrowser
import asyncio

async def main():
    browser = CekiBrowser(
        token="your_agent_token",
        endpoint="https://api.ceki.me/mcp/agent"
    )

    # Rent a session
    session = await browser.rent(headless=False)
    print(f"Session: {session.id}")

    # Navigate
    await session.navigate("https://example.com")

    # Execute JavaScript
    title = await session.evaluate(
        "document.title"
    )
    print(f"Page title: {title}")

    # Click at coordinates
    await session.click(500, 300)

    # Type text
    await session.type("Hello from Ceki!", "#my-input")

    # Get page content
    html = await session.get_html()
    print(f"Page has {len(html)} characters")

    # Take screenshot
    await session.screenshot("/tmp/screenshot.png")

    # Clean up
    await session.stop()

asyncio.run(main())

Real-World Use Cases

1. AI Agent Web Automation

AI agents need to interact with web services that have anti-bot protection. Browser rental APIs give them access to real browsers that look like human users:

  • LLM agents booking appointments on scheduling platforms
  • AI assistants filling out multi-step forms
  • Automated data extraction from JS-heavy SPAs

2. E2E Testing with Real Devices

Traditional testing uses headless browsers that miss production-only bugs. Real browser sessions catch issues with WebGL rendering, font loading, and extension interactions.

3. Web Scraping at Scale

Rotate through hundreds of residential IPs and browser fingerprints to collect data without getting blocked. Each session is a clean browser environment with a unique fingerprint.

Best Practices

  • Session lifecycle: Always stop sessions when done to avoid idle charges
  • Error handling: Implement retry logic — sessions can occasionally fail on provider disconnect
  • Respect rate limits: Even with real browsers, aggressive request rates trigger rate limiting
  • Use human-like delays: Add random delays between actions to appear more natural
